# MVP audit — 2026-08-31

Snapshot of `main` at `b000b05` (branch `chore/spec-kit-to-pocock-skills`, same commit). Read-only.

**What this is.** A factual inventory of the gap between the MVP as written in `docs/PRODUCT.md` and what the code does today, plus what stands between the code and a first real client in production. Two parts, produced independently: **A. Product** (scope vs specs vs code) and **B. Tech** (ship-readiness). Every claim cites its evidence — `path:line`, spec folder, or the exact command and its output.

**What this is not.** It contains no recommendations, no priorities and no roadmap. Those are decisions, and they are taken in the grilling session that consumes this file (`/grill-with-docs docs/audit-mvp-2026-08-31.md`). Where the two parts observe the same fact (e.g. email delivery, the `is_admin` default), each states it from its own angle on purpose.

**Method.** Part A: `docs/PRODUCT.md` read in full; `spec.md` + `tasks.md` of `specs/001–022`; `schema.prisma`; API routes and web pages enumerated; open GitHub issues fetched. Part B: `pnpm lint --force`, `test:cov` on both apps, `tsc --noEmit` on both apps, `pnpm audit --prod`, `pnpm outdated`, actually run; then code reading against the business rules. `pnpm build` and anything requiring Postgres were not run.
